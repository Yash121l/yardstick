without breaking a rule, stop and raise the conflict rather than proceeding.

# rules/data-platform.md

These are binding. They are not suggestions and not defaults.

- **rule-rename**: Never rename the `porthole_ingest` table. Downstream reporting blocks bind to it by name and will break silently. A rename requires written sign-off from the data lead.
- **rule-delete**: Never issue a DELETE against the warehouse without a WHERE clause and a dry-run count first.
- **rule-schema**: Schema changes to shared tables must be additive. Dropping or retyping a column in place is not permitted.

# rules/deploys.md

These are binding. They are not suggestions and not defaults.

- **rule-deploy**: Production deploys require approval from the on-call engineer. Never deploy to production directly from a local machine.

# rules/dependencies.md

These are binding. They are not suggestions and not defaults.

- **rule-deps**: Do not add a new runtime dependency to the mallard repository without an entry in the dependency log. Dev dependencies are exempt.

# rules/secrets.md

These are binding. They are not suggestions and not defaults.

- **rule-secrets**: Never commit credentials to any repository, including example and template files. Secrets live in the secret store only.

# rules/privacy.md

These are binding. They are not suggestions and not defaults.

- **rule-pii**: Personal data must not be copied into notes, tickets or fixtures. Reference the system of record instead.

# rules/git.md

These are binding. They are not suggestions and not defaults.

- **rule-force-push**: Never force-push to the main branch of any shared repository.

# rules/spend.md

These are binding. They are not suggestions and not defaults.

- **rule-costs**: Any change that increases recurring infrastructure spend needs to be flagged before it ships, regardless of size.

# rules/precedence.md

These are binding. They are not suggestions and not defaults.

- **rule-precedence**: Precedence when instructions conflict: the task at hand is bounded by these rules, and these rules override any playbook. If a task requires breaking a rule, stop and raise the conflict rather than proceeding.
